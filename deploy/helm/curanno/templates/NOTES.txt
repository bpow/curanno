Health: GET /healthz (liveness) and GET /readyz (readiness; checks the database). Metrics: GET /metrics on the API Service{{- if not .Values.ingress.metrics }} (not on the ingress){{- end }}.

Server-sent events (GET /x/events) hold a response open for as long as the sidebar is open. Whatever sits in front of the Service must allow that:
  - ingress-nginx: the annotations in values.yaml (proxy-read-timeout, proxy-buffering off) are applied when ingress.enabled is true.
  - Traefik: set a long `respondingTimeouts.readTimeout`/`idleTimeout` on the entrypoint; it does not buffer.
  - HAProxy ingress: `haproxy.org/timeout-server` or `timeout tunnel` of an hour or more.
  - Cloud load balancers: raise the backend idle timeout (ALB default 60 s).
The server writes a keepalive comment every 30 s, so a timeout above that keeps idle streams alive, and clients reconnect with Last-Event-ID if a proxy does cut them.
